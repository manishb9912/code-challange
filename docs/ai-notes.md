One line per course change, AI-introduced bug, or non-obvious choice. Raw material for AI_USAGE.md; the human verifies each entry.

- Plan: verified the Fake Store response shape with a live fetch before writing the spec. It matched the brief (numeric ids, `rating.rate`, `jewelery`, `men's clothing`), and some titles have trailing spaces, so the mapper trims them.
- Environment: Docker was not installed locally. The human chose to install it before the compose slice instead of shipping compose files unverified.
- Repo: the branch was `master` with no commits; renamed it to `main` so the PR can target `main` as the brief requires. Added `.gitattributes` (LF) because global `core.autocrlf` would have produced CRLF files.
- Tooling: the newest majors were incompatible. typescript-eslint requires TS < 6.1, so TypeScript is pinned to 6.0.3 rather than 7.x.
- Tooling (course change): first installed ESLint 9 for `eslint-plugin-import`/`eslint-plugin-react` peer support. npm flagged ESLint 9 as unsupported, so switched to ESLint 10 + `eslint-plugin-import-x` + `@eslint-react/eslint-plugin`, which are maintained equivalents. Updated the rule names in CLAUDE.md to match.
- Tooling: `packages/shared` exposes a `source` export condition, so the api, web, Vitest and tsx consume the TS source directly (no "build shared first" step before tests). Production builds resolve `dist` through the default condition.
- Tooling: Vite `build.modulePreload.polyfill: false`, so the build never needs an inline script and stays compatible with `script-src 'self'`.
- Local Node is v24; the target is Node 22 (`.nvmrc`, Docker and CI). `engines` is `>=22`.
- API: Fastify v5 types reject a numeric `trustProxy`, so it's an explicit `(addr, hop) => hop < TRUST_PROXY_HOPS` function (same semantics as proxy-addr's numeric form).
- API: turned off `@typescript-eslint/require-await` in the config (not inline). Fastify's documented way to return a value is an async handler, so the rule only produced noise.
- API: log redaction uses explicit paths rather than `*.message`, because a wildcard would also censor `err.message` and make error logs useless.
- API: added `URI_TOO_LONG` (414) to the shared error codes for the URL-length guard instead of overloading `VALIDATION_ERROR`.
- Review: the security tests passed on the first run, so I mutation-checked them (disabled redaction, disabled the Origin check). 3 tests failed as expected, then the code was restored.
- Process slip (mine): committed slice 3 with 3 lint errors because I piped `npm run lint` through `tail`, which hid its exit code. Fixed them in a follow-up commit (no history rewrite) and added `npm run verify` as an unpiped gate before every commit.
- Upstream quirk (verified with curl): Fake Store returns **200 with an empty body** for unknown product ids, not 404, so the adapter treats an empty body as "not found". It also never redirects, so `redirect: 'error'` is safe and blocks redirect-based SSRF.
- Cache design: `getProduct` is cached per id, including "not found" (negative caching). That stops repeated unknown ids fanning out to the upstream; the in-memory cache is bounded (1000 entries, oldest evicted) so random ids can't grow memory. Stale entries are kept for 12× TTL so the cache can serve stale data on error.
- Adapter: non-numeric ids short-circuit to "not found" without a request (Fake Store only has numeric ids). This lives in the adapter because it's Fake Store knowledge, not domain knowledge.
- Tooling: the Bash tool fails to parse heredocs containing apostrophes (e.g. `men's clothing`), so source files are written with the file-write tool instead.
- Bug caught by tests (course change): the brief asked for two enquiry windows (5/min and 20/hour). My first version combined route `config.rateLimit` with an extra `app.rateLimit()` hook. Tests showed the per-minute limit was silently skipped. Reading the plugin source: `@fastify/rate-limit` runs only one limiter per request (a `req[rateLimitRan]` guard). Asked the human; they chose 5/min only, with the hourly/daily cap documented as an edge (AWS WAF) control. `RATE_LIMIT_ENQUIRY_PER_HOUR` was removed.
- Boundary fix: the email builder in `domain/` first imported `OutgoingEmail` from `ports/` (a violation of the dependency rule), so the email types moved to `domain/email.ts` and the Mailer port imports them.
- Enquiry validation happens once, at the HTTP edge (route body schema = shared `EnquirySchema`). The service takes the already-typed `Enquiry` rather than re-parsing.
- An unknown `productId` on an enquiry returns 400 with a `productId` field error, not 404: it's an invalid form submission, not a missing resource.
- Manual check against the live Fake Store (outside tests): featured order kept, unknown id skipped, labels and slugs correct, 404/502 envelopes correct. It surfaced a Fastify deprecation (`requestIdLogLabel` → `logController`), now fixed and re-verified (0 warnings; proxy request id appears in logs).
- Observed a search limitation on real data: "mens cotton" also matches "Womens T Shirt" because substring matching finds "mens" inside "womens". This is spec-compliant (plain `includes`). Recorded as a known limitation; word-boundary matching and stemming come with a real search index.
- Web bug (mine): the API client called `fetch('/api/v1/...')` with a relative URL. Browsers resolve it against the page, but Node/undici (used under jsdom) doesn't, so every request fell into the network-error branch. The first test run caught it, and the client now resolves URLs against `window.location`.
- Web: the API client validates every response against the shared zod schemas, so contract drift fails loudly in one place. Cost: zod ships in the main bundle (~119 KB gzipped total). Noted as an optimisation (e.g. `zod/mini`), not done.
- Web: verified the production build is CSP-compatible: no inline `<script>`/`<style>`, no `style=` attributes; lazy route CSS loads as external files.
- Web: the search input is re-keyed on the URL term instead of syncing state in an effect, so back/forward resets it without an effect-driven state update.
- Process slip (mine, second time): committed slice 8 while `verify` failed, because the command joined `verify` and `git commit` with `;` instead of `&&`. Every commit is now chained directly as `npm run verify && git commit`.
